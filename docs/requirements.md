# 拍立得记录产品需求草案

更新日期：2026 年 10 月 11 日

让地下偶像粉丝在现场或活动结束后快速记录拍立得，随时查到和谁拍了多少张、花了多少钱，并可通过照片回顾收藏。

## 已确认的范围

| 项目 | 需求 |
| --- | --- |
| 使用方式 | 现场随手记与事后统一补录都需要支持 |
| 核心统计 | 同时统计拍立得张数和花费 |
| 拍立得类型 | 支持区分普通、签名、合照等类型 |
| 照片 | 上传可选，不上传也能完整使用记录和统计功能 |
| 相册 | 已上传的照片可以集中浏览、回顾 |
| 数据保存 | 支持备份与导出，便于长期保存和迁移 |
| 代码仓库 | YihengBrianWu/cheki_record |
| 产品形态 | 小程序、App Store 应用或网页版后续决定 |

以下流程、字段、统计口径和页面结构是实现建议，作为后续原型讨论的基础。

## 核心使用流程

### 现场快速记录

1. 创建或进入当天的一次偶活，日期默认今天。
2. 从常用或最近记录的偶像中选择对象，也可以直接新增偶像。
3. 填入张数、类型和金额后保存；来不及填金额时允许暂存待补。
4. 同一场再次拍摄时，追加一笔或在已有明细上增加张数。
5. 当场查看该活动的累计张数和已记录花费。

活动名称、地点和照片都不阻碍快速保存。追加与修改要有清楚区分，保存后可撤销误操作，重复点击保存不能生成重复记录。

### 事后统一补录

1. 选择实际活动日期，创建一场活动。
2. 在同一页面连续添加多位偶像的拍摄明细。
3. 为同一位偶像录入不同类型或不同价格的拍立得。
4. 检查整场合计并保存。
5. 可稍后补金额、修改类型或上传照片。

同一天可以有多场活动；补录日期与记录创建时间分开，统计使用实际活动日期。

### 回顾与查找

- 按日期浏览活动，进入活动查看每位偶像的明细和整场合计。
- 进入偶像详情，查看累计张数、花费、出现过的活动和照片。
- 按月份、年份或自定义时间范围查看统计。
- 按活动名称、偶像或团体检索，并按类型筛选。

## 第一版功能与规则

### 活动和拍摄明细

一场活动包含多条拍摄明细；一条明细可记录同类拍立得的多张数量，无需为每张分别填表。

| 对象 | 建议信息 | 规则 |
| --- | --- | --- |
| 活动 | 日期、名称、地点、备注 | 日期必填，其他可选；名称为空时用日期展示 |
| 偶像 | 昵称、所属团体、头像 | 昵称必填，团体和头像可选；支持个人偶像 |
| 拍摄明细 | 活动、偶像、类型、张数、金额、照片 | 张数为正整数；金额和照片可后补 |
| 类型 | 名称 | 提供普通、签名、合照等选项，并允许自定义 |

同一场、同一位偶像允许多条明细，用于区分类型、价格或多次追加。支持编辑和删除；相应统计自动重算。

偶像改名、换团或毕业不会删除历史记录。历史活动保留当时填写的团体信息，同一人的累计统计仍按固定身份关联。误建重复偶像后的合并操作可后续补充。

### 张数和金额

- 张数以手动记录为准，独立于已上传照片的数量。
- 金额支持直接填写该笔实付总额；也可填写单价，按张数计算总额。
- 实付总额是统计依据，允许优惠、赠送或不同定价；不强制总额永远等于参考单价乘张数。
- 未填写金额与明确填写 0 元分别保存；未填写的记录仍计张数，花费展示为“已记录金额”，并提示有多少笔待补。
- 快速增加张数时，只有明确采用固定单价计算的明细才同步增加金额；手动总额需要提示核对。
- 第一版建议默认人民币。若后续增加多币种，必须分币种统计，不能直接相加。
- 默认只统计拍立得支出，门票、交通、餐饮等费用暂不纳入。

### 类型和合照

支持按类型录入、筛选和统计。普通、签名、合照不是完全互斥的概念，例如合照也可能带签名；原型阶段再决定使用组合类型，还是拆成拍摄形式与签名状态。

若合照支持关联多位偶像，一张合照在活动、月份和全局总数中只算一张，花费只算一次。每位参与偶像的详情可以查到这张合照，但跨偶像汇总必须去重。合照金额在个人统计中如何归属，需在实现前明确。

### 可选照片和相册

- 每笔记录可不上传照片，也可上传一张或多张，支持保存后再补。
- 不要求照片数等于拍立得张数，一张照片也可能拍下多张拍立得。
- 上传、替换或删除照片都不改变已记录的张数和金额。
- 相册按活动日期浏览，支持按偶像和活动筛选、查看大图并返回对应记录。
- 上传失败时保留数量与金额记录，允许重试；已保存的记录不因附件失败而丢失。
- 默认作为个人收藏使用，公开分享和社区功能不在当前范围内。

### 统计

| 维度 | 展示内容 |
| --- | --- |
| 单场活动 | 总张数、已记录花费、待补金额笔数、各偶像及类型明细 |
| 单个偶像 | 累计张数、已记录花费、涉及活动数、历史记录和照片 |
| 时间范围 | 本月、本年、全部或自选区间的张数与花费 |
| 拍立得类型 | 各类型的张数与花费 |

统计统一从原始明细计算。修改、删除和补录后立即更新；“活动数”按不同活动计算，同一场的多笔记录不重复计场次。

### 备份、恢复和导出

备份用于恢复完整数据，导出用于在其他工具中查看和分析，两者分别提供。

- 建议完整备份为 ZIP，包含版本信息、结构化记录、照片和关联关系；只有照片链接不算完整备份。
- 支持从备份恢复活动、偶像、类型、拍摄明细及照片。先校验文件，再展示数据数量、照片数量和覆盖范围。
- 第一版建议采用明确的整库恢复方式，恢复前保留当前数据备份；格式错误或恢复失败不破坏原有数据。
- 支持将拍摄明细导出为 CSV，包含日期、活动、偶像、团体、类型、张数、实付金额和币种。
- CSV 中金额缺失保持为空，明确的零元保留为 0；CSV 不承载照片，也不能替代完整备份。
- 恢复同一份备份不会重复增加记录；恢复后金额、张数和照片关联应与原数据一致。

自动云备份、多设备同步和离线策略受平台与账号方案影响，后续确定；不能仅用“导出 CSV”代替用户提出的备份需求。

## 建议的页面结构

| 页面 | 主要操作 |
| --- | --- |
| 首页 | 看本月张数与花费，进入最近活动，快速记一笔 |
| 活动列表与详情 | 按日期回顾、新建活动、批量录入或追加拍摄明细 |
| 偶像列表与详情 | 管理常拍对象，查看个人累计、活动历史和照片 |
| 相册 | 按日期翻看照片，按活动或偶像筛选 |
| 统计 | 切换时间范围，查看偶像和类型分布 |
| 设置与数据管理 | 管理类型，备份、恢复和导出 |

这是页面职责划分，具体导航和布局在原型阶段确定，不绑定任何平台。

## 验收场景

1. 一场活动录入 A 普通拍立得 2 张、实付 100 元，A 签名拍立得 1 张、实付 80 元，B 普通拍立得 3 张、实付 150 元。整场显示 6 张、330 元，A 显示 3 张、180 元，B 显示 3 张、150 元。
2. 给其中一笔 3 张的记录上传 1 张照片，该笔仍统计为 3 张；删除照片也不改变张数和金额。
3. 新增一笔 1 张但未填金额的记录，张数加 1，已记录金额不变，并出现待补金额提示；补填后各相关统计同步更新。
4. 同一天创建两场活动，记录分开保存；按日或按月查看时能够正确汇总。
5. 把记录日期改到上月后，该笔从本月统计移到上月；修改数量或删除记录后，各页面合计一致。
6. 对采用固定单价计算的明细追加 1 张，按该单价更新金额；对手动填写实付总额的明细追加张数时，提示核对金额。
7. 备份后在空数据环境恢复，活动、偶像、类型、张数、金额和照片关联保持一致；再次恢复同一备份不重复计数。
8. 导出的 CSV 能区分未填金额和明确的 0 元；无照片记录仍能正常导出、恢复和统计。

## 后续需要确定的选择

- 产品形态及是否需要账号、多设备同步和断网记录。
- 类型采用单项组合，还是拆分拍摄形式与签名状态。
- 合照是否关联多位偶像，以及个人花费统计中的归属方式。
- 照片存储位置、大小限制和原图保存策略。
- 第一版是否只使用人民币。

当前阶段先完成需求与交互原型，再据此选择技术方案。上述待定项不妨碍先讨论主流程。
