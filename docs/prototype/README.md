# 推活日记交互原型

这个目录用于评审产品流程，包含 8 个手机页面、三张原型总览图以及可点击的浏览器演示。它不是已完成的正式应用。

## 打开方式

用浏览器直接打开 `index.html`，或从仓库根目录启动静态服务器，再访问 `/docs/prototype/index.html`。不依赖网络字体、图片服务或外部脚本。

桌面侧栏可切换全部页面，页面内按钮连接相应流程。底部导航支持日记、偶像、相册与统计。左下角可重置演示数据；刷新也会重置。页面内返回与浏览器后退 / 前进可恢复对应页面；直接打开子页面时可返回首页。预览高度会适应窗口，底部操作不会落到屏幕外。

## 可体验的操作

- 首页悬浮操作区始终提供快速记录与批量记录入口，列表底部留白避免遮挡最后一条。
- 新增偶像或团体，在偶像页面或首页发起记录。
- 选择日期、个人 / 团体 / 特殊分类与类型；活动可留空；单选自定义类型，支持创建、改名和删除；录入张数、单价或实付总额。
- 金额留空或明确填零，查看统计中的差异。
- 保存、编辑、删除、撤销、单价记录追加一张。
- 手动实付记录追加时进入编辑页核对金额。
- 批量记录的明细添加、编辑、增减数量、移除，活动完全选填。
- 本地选择照片并随记录保存、查看大图、删除照片而保持张数不变。
- 团切选择一个团体；特殊可选择多位偶像，数量独立、不增加常规或个人切数。
- 按个人、团体或特殊筛选相册；特殊收藏还可按参与偶像查找。
- 实际下载 CSV，预览模拟 ZIP 备份与恢复流程。

## 演示边界

所有人物、团体与活动均为虚构。初始为 3 个记录日、9 笔记录、17 张常规 + 1 张特殊、1100 元已记录总花费（含特殊 120 元）、1 笔待补与 4 张示例照片。

修改只保留在当前 JavaScript 内存中，上传图片通过本地文件读取，不发送到任何服务器。刷新后丢失修改，因此不能用来保存真实收藏。

尚未实现账号、持久化、服务端幂等、离线同步、云端照片存储、真实 ZIP 备份与恢复、完整草稿管理、活动管理、偶像改名、日期区间检索、正式可访问性支持。PRD 中的正式产品验收标准不等于原型已经实现全部功能。

类型由用户自定义并单选，可创建、改名、删除。个人与团体记录都只选一个对象；特殊记录可关联多人，不计入常规切数。特殊花费计入总花费、不分摊给个人，属于当前设计建议。

## 已验证

2026 年 10 月 11 日，使用本机 Chrome / Playwright 验证：

- 8 个主页面和 4 个团体 / 特殊变体可渲染，390 像素与 320 像素宽度没有横向溢出或页面运行错误。
- 36 项交互检查通过（22 项基础流程、14 项团体与特殊流程），重点包括：无活动保存、按日期汇总、补填与清除活动、日期修改、数量与金额校验、照片操作、批量记录、CSV 分类、特殊参与者和空活动导出与模拟恢复；团切不分摊、特殊不计入常规、分类切换重新归类。
- 返回与布局回归覆盖浏览器后退 / 前进、页面内返回、直接打开子页面、旧链接与较矮视口。
- 14 页 PDF 已经 Poppler 渲染并检查布局；文本提取确认每页包含可读取的正文。

这些检查验证交互原型，不替代正式产品的持久化、恢复正确性、真机或可访问性测试。

## 重新生成交付物

从仓库根目录执行，需要 Node.js、Playwright、Chrome / Chromium、Python、Pillow、reportlab 和包含中文字形的 TrueType 字体。依赖路径通过环境变量提供，原型本身无需这些依赖。

```sh
# Playwright 已安装在 Node 可解析的位置；可指定本机 Chrome 路径。
CHROME_PATH=/path/to/chrome node scripts/render-prototype.mjs

# 返回导航与短窗口布局的回归检查。
CHROME_PATH=/path/to/chrome node scripts/check-navigation.mjs

# macOS 默认使用 Arial Unicode；其他系统需设置 CHEKI_CJK_FONT。
CHEKI_CJK_FONT=/path/to/chinese-font.ttf python3 scripts/build-prd.py
```

先生成截图，再生成总览图与 PDF。图文内容的主要维护位置是 `docs/PRD.md`、本目录三个原型源文件和两个构建脚本。
